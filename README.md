# 身份认知插件（Alcpare.identity）

让她知道**当前跟她说话的人是谁**（主人 / 朋友 / 群友），从而用对态度。
纯手动白名单，**不调用任何 LLM、不写数据库、没有定时任务**。

---

## 一分钟上手

1. WebUI 插件页确认本插件已加载（或重启麦麦）。
2. 打开配置里的 **身份名单 → roster**，加一行：

```toml
roster = """
100000001 = 主人
100000002 = 朋友        ← 加一行就行（QQ号 = 档位）
"""
```

3. **保存即生效，不用重启** ✓

**不用写名字**：她在聊天里看到的显示名（群名片优先，其次昵称）会实时取用，
所以你或对方改群名片、改昵称都不影响。

---

## 配置项（一共 9 项，通常只改第 1 项）

### 1️⃣ 名单与三档分寸（主要就改这四项）

| 配置项 | 作用 | 怎么改 |
|---|---|---|
| `roster` | 白名单：每行 `QQ号 = 档位`（主人 / 朋友），`#` 开头是注释 | 加人、改档位 |
| `owner_style` | **「主人」档的语气 + 关心到什么程度** | 想让她更黏/更收敛，改这段 |
| `friend_style` | **「朋友」档**的语气 + 关心程度 | 同上 |
| `member_style` | **「群友」档**（名单外的人也按这档） | 同上 |
| `default_label` | 名单外的人按哪一档 | 一般保持「群友」 |

> 💡 写这三段文案的要诀：**写"到什么程度"，别写具体行为例子**。
> 比如写"关心点到为止、别反复念同一件事" ✓；
> 写"比如催他睡觉" ✗ —— 她会照着这个例子套，反而更容易唠叨。

### 2️⃣ 开关（默认值就是推荐值）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `inject_to_planner` | true | 在她**决定要不要回**之前注入 |
| `inject_to_replyer` | true | 在她**写回复**之前注入 |
| `inject_for_others` | false | 名单**外**的人也注入？关闭=只对名单内生效（省 token） |
| `log_injections` | true | 每次注入写日志，方便核对 |

（插件段还有一个总开关 `plugin.enabled`）

## 它到底往提示词里塞了什么

```
【内部参考 · 只给你自己看，不要向别人解释或复述这份说明】
- 本条消息来自：Alcpare（你的主人）。<owner_style 的内容>
- 其他所有人按普通群友对待：<member_style 的内容>
- 这是你的内部认知，正常聊天时不用提它，也别主动给谁贴"档位"标签；
  但如果对方问起你们的关系，就自然承认、按关系说话，不用回避。
```

## 设计要点

| 点 | 说明 |
|---|---|
| **QQ 号不进提示词** | QQ 只存在于插件内存表 `msg_id → user_id`；注入文本还会过一遍「5 位以上连续数字」自检，命中就**拒绝注入**并记警告 |
| **当前说话者精确判定** | 按消息 ID 反查（兼容宿主两种格式：`<message msg_id="…">` 与 `[msg_id:…]`），不靠名字匹配 → **同名、改名都不怕** |
| **同一轮只注入一次** | 一轮里 planner 可能循环多回合；插件按「阶段+会话+消息ID」去重，避免同一段话被反复强调 |
| **重启不丢** | 映射落盘在 `data/plugins/Alcpare.identity/speakers.json`，重启后恢复（频率调度会延迟几十秒才处理消息，必须扛得住重启） |
| **零副作用** | 名单为空 / 说话者不在名单里 → **完全不注入**，行为与没装插件一致 |
| **失败不影响收发** | 入口钩子整体包了异常处理，失败只记 WARNING |

## 排查（日志里搜 `[身份]`）

| 日志 | 含义 |
|---|---|
| `已加载：名单 N 人（…）注入阶段=… 名单外=… 恢复映射 M 条` | 启动状态 |
| `入口记录: msg_id=… user_id=… session=…` | 收到消息并记下了说话者（DEBUG） |
| `已注入(planner/items/SystemMessageItem)：某某 → 主人` | 注入成功 ✓ |
| `[跳过/planner] 说话者不在名单（且只对名单内生效）` | 正常跳过（名单外的人） |
| `[跳过/planner] 本轮已注入过，跳过` | 去重生效（正常） |
| `[跳过/…] 无法定位当前说话者` | 宿主没给 items 或上下文里没有消息 ID（版本变了需要适配） |
| `注入文本含长数字，已拒绝注入` | 文案里混进了号码，检查后重存 |

## 已知限制

- **旧消息里的同名混淆无法在文本层解决**：宿主给模型的输入里只有显示名（`UserMessageItem` 不带 user_id），
  插件只能保证**当前这条**准确；同名时会给一句"分不清就别区别对待"的提示。
- **长消息 ID 的映射依赖宿主规则**：宿主的 `to_display_message_id` 会把超过 12 字符的消息 ID 缩短成
  `m` + 6 位别名，插件按同样的规则复刻了一份。**若宿主未来改动该规则**，长 ID 的精确映射会静默失效，
  此时插件退化为「按会话最近一条消息」定位 —— 由于频率调度可能延迟几十秒才处理消息，这种兜底
  **可能把同一会话里较早的说话者当成当前者**。若宿主将来提供「按 message_id 查发送者」的能力，插件会优先换用它。
- 依赖宿主钩子：`chat.receive.before_process`、`maisaka.planner.before_request`、
  `maisaka.replyer.before_model_request`。**实测环境：MaiBot 1.3.4 / SDK 2.9.0**；
  manifest 里的兼容区间按实测收紧为 `host >= 1.3.4`、`sdk >= 2.9.0`。

## 隐私与落盘（磁盘上留了什么）

| 位置 | 内容 | 说明 |
|---|---|---|
| `data/plugins/Alcpare.identity/speakers.json` | **明文**的 `msg_id → {user_id, 显示名, 会话, 时间}` 映射 | 仅用于"重启后仍能定位被延迟处理的消息"。**不含任何消息内容**；TTL 6 小时、最多 2000 条；原子写入（先写临时文件再 `os.replace`） |
| 日志 | 只记**遮蔽后**的号码（如 `137***257`）与显示名 | 号码不落日志，避免日志被贴出时泄露身份名单 |

**不写宿主数据库、不碰宿主配置、不删除任何文件** ✓
**QQ 号永不进入提示词** ✓ —— 但请注意：这是"提示词层面"的保证，磁盘上仍有上面那份明文映射 ✓

配置文件 `config.toml` 含有你的名单（真号码），**已被 `.gitignore` 排除**，不会随插件进仓库 ✓
