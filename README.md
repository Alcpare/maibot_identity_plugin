# 身份认知插件（Alcpare.identity）

让她知道**当前跟她说话的人是谁**（主人 / 朋友 / 群友），从而用对态度。
纯手动白名单，**不调用任何 LLM、不写宿主数据库、没有定时任务**。

- 当前版本：**1.0.7**（测试版）
- 兼容：MaiBot **≥ 1.3.6**（需要 `custom_pages` 能力）/ 插件 SDK ≥ 2.9.0
- 联系方式：**1373558257@qq.com**

---

## 一分钟上手

### 方式一：WebUI 图形界面（推荐）

1. 在 WebUI 插件页确认本插件已加载。
2. 侧边栏或插件工作区里打开 **「身份认知」** 页面。
3. 点「添加」→ 填 QQ 号 → 选身份（主人 / 朋友 / 群友）→ 拖关心频率 → 保存。

**保存即生效，不用重启** ✓

### 方式二：直接改配置

```toml
[identity]
roster = [
  { user_id = "100000001", label = "主人", care_level = 4 },
  { user_id = "100000002", label = "朋友", care_level = 2 },
]
```

也兼容旧版的多行文本写法（会自动迁移成上面的列表格式，旧配置升级不会丢名单）：

```toml
roster = """
100000001 = 主人
100000002 = 朋友        # 也可以写注释
"""
```

**不用写名字**：她在聊天里看到的显示名（群名片优先，其次昵称）会实时取用，
所以你或对方改群名片、改昵称都不影响。

## 配置项

### 1️⃣ 名单（`roster`）

列表格式，每人三项：

| 字段 | 说明 |
|---|---|
| `user_id` | QQ 号（只用于内部识别，**永不会进入提示词**） |
| `label` | 身份：`主人` / `朋友` / `群友` |
| `care_level` | 关心频率：`1`=不提 / `2`=偶尔 / `3`=正常 / `4`=经常 |

> **容错**：单条填错不会拖垮整个插件。
> - `label` 填了不认识的档位 → **跳过这个人**并打警告，其余人正常。
> - `care_level` 超出 1~4 → **保留这个人**，频率回落到默认值 3。
> - `user_id` 为空 → 跳过这条。
> - 支持全角数字（`１３７…` 会自动转半角）。

### 2️⃣ 三档语气文案

| 配置项 | 作用于 |
|---|---|
| `owner_style` | 「主人」档（最亲近的人） |
| `friend_style` | 「朋友」档（熟人） |
| `member_style` | 「群友」档（普通群成员，也是名单外人的默认档） |
| `default_label` | 名单外的人按哪一档，默认「群友」 |

关心频率的四档措辞：

| 配置项 | 对应档位 |
|---|---|
| `care_none` | 1 — 不主动关心 |
| `care_rare` | 2 — 偶尔提一句 |
| `care_normal` | 3 — 自然关心，一两句 |
| `care_often` | 4 — 可以多关心几句 |

> 💡 写文案的要诀：**写"到什么程度"，别写具体行为例子**。
> 比如写"关心点到为止、别反复念同一件事" ✓；
> 写"比如催他睡觉" ✗ —— 她会照着这个例子套，反而更容易唠叨。

### 3️⃣ 开关（默认值就是推荐值）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `inject_to_planner` | true | 在她**决定要不要回**之前注入 |
| `inject_to_replyer` | true | 在她**写回复**之前注入 |
| `inject_for_others` | false | 名单**外**的人也注入？关闭=只对名单内生效（省 token） |
| `log_injections` | true | 每次注入写日志，方便核对 |

（插件段还有一个总开关 `plugin.enabled`）

## WebUI 自定义页面

插件自带一个图形配置页面（`webui.json` + `webui/identity.html`），需要宿主支持 `custom_pages`（MaiBot 1.3.6+）。

页面上可以直接：

- 增删人、改 QQ 号、选身份档位
- 用滑块调关心频率（1~4）
- 编辑三档语气文案和四档关心措辞
- 一键保存，写回 `config.toml` 并热重载

页面在插件的沙箱 iframe 里运行，通过 `window.maibot.query/action` 与宿主通信（不走 `fetch`，CSP 已禁止）。

## 它到底往提示词里塞了什么

```
【内部参考 · 只给你自己看，不要向别人解释或复述这份说明】
- 本条消息来自：某某（你的主人）。<owner_style 的内容> <对应关心档位的措辞>
- 其他所有人按普通群友对待：<member_style 的内容> <care_normal 的措辞>
- 这是你的内部认知，正常聊天时不用提它，也别主动给谁贴"档位"标签；
  但如果对方问起你们的关系，就自然承认、按关系说话，不用回避。
```

名单外的人（`inject_for_others=true` 时）会显示为「你的群友」，用 `member_style` 的措辞。

## 设计要点

| 点 | 说明 |
|---|---|
| **QQ 号不进提示词** | QQ 只存在于插件内存表 `msg_id → user_id`；注入文本还会过一遍「5 位以上连续数字」自检，命中就**拒绝注入整条**并记警告 |
| **当前说话者精确判定** | 按消息 ID 反查（兼容宿主两种格式：`<message msg_id="…">` 与 `[msg_id:…]`），不靠名字匹配 → **同名、改名都不怕** |
| **重名提示** | 同一会话里出现两个同名的人时，注入文本会带一句"分不清谁是旧消息、不要区别对待"，避免她认错人 |
| **同一轮只注入一次** | 一轮里 planner 可能循环多回合；插件按「阶段+会话+消息ID」去重，避免同一段话被反复强调 |
| **重启不丢** | 映射落盘在 `data/plugins/Alcpare.identity/speakers.json`，重启后恢复（频率调度会延迟处理消息，必须扛得住重启） |
| **零副作用** | 名单为空且 `inject_for_others=false` → **完全不注入**，并在启动日志打一条明确警告 |
| **失败不影响收发** | 入口钩子整体包了异常处理，失败只记 WARNING |
| **并发安全** | 同一消息并发多次请求只会注入一次；不同消息互不干扰 |

## 排查（日志里搜 `[身份]`）

| 日志 | 含义 |
|---|---|
| `已加载：名单 N 人（…）注入阶段=… 名单外=… 恢复映射 M 条` | 启动状态 |
| `警告：名单为空，插件不会注入任何身份信息` | 名单是空的，需要添加至少一个人 |
| `入口记录: msg_id=… user_id=… session=…` | 收到消息并记下了说话者（DEBUG） |
| `已注入(planner/items/SystemMessageItem)：某某 → 主人` | 注入成功 ✓ |
| `[跳过/planner] 说话者不在名单（且只对名单内生效）` | 正常跳过（名单外的人） |
| `[跳过/planner] 本轮已注入过，跳过` | 去重生效（正常） |
| `[跳过/…] 无法定位当前说话者` | 宿主没给 items 或上下文里没有消息 ID（版本变了需要适配） |
| `注入文本含长数字，已拒绝注入` | 文案里混进了号码，检查后重存 |
| `名单项 xxx=yyy 档位无法识别，已跳过` | 名单里有人的身份填错了，已跳过该人 |

## 已知限制

- **旧消息里的同名混淆无法在文本层解决**：宿主给模型的输入里只有显示名（`UserMessageItem` 不带 user_id），
  插件只能保证**当前这条**准确；同名时会给一句"分不清就别区别对待"的提示。
- **长消息 ID 的映射依赖宿主规则**：宿主的 `to_display_message_id` 会把超过 12 字符的消息 ID 缩短成
  `m` + 6 位别名，插件按同样的规则复刻了一份。**若宿主未来改动该规则**，长 ID 的精确映射会静默失效，
  此时插件退化为「按会话最近一条消息」定位 —— 由于频率调度可能延迟几十秒才处理消息，这种兜底
  **可能把同一会话里较早的说话者当成当前者**。若宿主将来提供「按 message_id 查发送者」的能力，插件会优先换用它。
- 依赖宿主钩子：`chat.receive.before_process`、`maisaka.planner.before_request`、
  `maisaka.replyer.before_model_request`。**实测环境：MaiBot 1.3.6+ / 1.3.19**（`custom_pages` 需要 1.3.6+）。

### 三个钩子都是 SDK 正式内置 Hook

依据官方文档 [Hook 处理器 · 内置 Hook 清单](https://docs.mai-mai.org/plugin/hooks)：

| 钩子 | 文档描述 | abort | 改参 |
|---|---|---|---|
| `chat.receive.before_process` | 入站消息执行 `SessionMessage.process()` 前 | ✅ | ✅ |
| `maisaka.planner.before_request` | Maisaka 规划器请求模型前 | ❌ | ✅ |
| `maisaka.replyer.before_model_request` | replyer 构造完最终 `messages` 后、请求模型前 | ❌ | ✅ |

两点补充说明：
- 后两个钩子**不允许 abort**，所以本插件全部使用 `error_policy=ErrorPolicy.SKIP`（用 `ABORT` 会被 Host 拒绝注册）。
- 文档写明：**传入未注册的 Hook 名称会导致插件注册失败**。本插件在真实 MaiBot 上加载成功，
  即这三个名字都已被 Host 注册（不是私有/实验入口）；插件市场里已收录的 `TAIY2020.smart_poke_plugin`
  与 `maibot-community.mai-repeater` 也在使用同一批钩子。

## 隐私与落盘（磁盘上留了什么）

| 位置 | 内容 | 说明 |
|---|---|---|
| `data/plugins/Alcpare.identity/speakers.json` | **明文**的 `msg_id → {user_id, 显示名, 会话, group（群号）, 时间}` 映射 | 仅用于"重启后仍能定位被延迟处理的消息"。**不含任何消息内容**；TTL 6 小时、最多 2000 条；原子写入（先写临时文件再 `os.replace`）。文件被写坏或手改过时会被整体忽略，不会影响插件加载 |
| `data/plugins/Alcpare.identity/identity_ui.json` | WebUI 页面保存的身份配置 | 启动时会用它覆盖 `config.toml` 里的对应项（WebUI 优先） |
| 日志 | QQ / 会话 ID / 群号都只记**遮蔽后**的形式（如 `137***257`）与显示名 | 号码不落日志，避免日志被贴出时泄露身份名单 |

**不写宿主数据库、不碰其他插件配置、不删除任何文件** ✓
**QQ 号永不进入提示词** ✓ —— 但请注意：这是"提示词层面"的保证，**磁盘上仍有上面那份明文映射（含明文群号）** ✓

配置文件 `config.toml` 含有你的名单（真号码），**已被 `.gitignore` 排除**，不会随插件进仓库 ✓
